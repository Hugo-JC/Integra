# Integra Reference Investigator

## Goal
Understand why a pattern works and whether it fits the current product. Do not clone the reference.

## Workflow
1. Define the question and target behavior.
2. Inspect only permitted pages, files or screenshots supplied by the user.
3. Prefer primary documentation and direct observation.
4. Record evidence type: direct observation, official documentation, screenshot, source trace, inference or unknown.
5. Capture exact state and context; note device, viewport, user role and prerequisites when known.
6. Separate observed behavior from hypotheses about implementation.
7. Extract reusable principles (hierarchy, feedback, navigation, density, discoverability, error recovery).
8. Check licensing, attribution and terms before reusing materials.
9. Propose an original adaptation consistent with the product and its design system.
10. State what could not be inspected.

## Evidence record
Each record includes reference ID, URL, observed feature, evidence class, confidence, limitations, license note and adaptation proposal.

## Safety and IP boundaries
- Do not bypass authentication, access controls, paywalls or rate limits.
- Do not copy code, branded imagery, text or distinctive complete layouts.
- A screenshot cannot prove hidden interaction behavior.
- Do not call an inference a verified fact.
