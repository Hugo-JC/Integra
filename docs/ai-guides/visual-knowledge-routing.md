# Visual knowledge routing

## Experience modes
- **Persuade:** visitors decide and act; landing pages, pricing and campaigns.
- **Operate:** users complete tasks; dashboards, editors, admin and product workflows.
- **Read:** users understand information; docs, articles and guides.
- **Experience:** users encounter an artifact or brand world; portfolios and showcases.

Choose mode per requested surface. A SaaS homepage may be Persuade while its workspace is Operate.

## Retrieval sequence
1. Normalize supplied brief, facts, constraints and existing tokens.
2. Identify surface mode and primary job.
3. Resolve exact niche only when evidence supports it; preserve alternatives if ambiguous.
4. Retrieve up to three source leads. Prefer normative/official sources for requirements and behavior; use galleries for inspiration.
5. Retrieve no more than three compatible token recipes.
6. Retrieve patterns only when their use conditions and content prerequisites are met.
7. Return rules and anti-patterns as review guidance. Evidence is needed before reporting defects.
8. Use examples to compare decisions; never reproduce layouts.
9. Produce acceptance checks and unresolved unknowns.

## Source authority
1. Normative standards for requirements.
2. Official platform/technical docs for behavior and API support.
3. Official design systems for their own tokens/components.
4. Directly inspected product interfaces for observed behavior within inspected scope.
5. Methodology/research sources for process principles.
6. Curated galleries/community posts for inspiration, not authority.

## Integrity
Usually one to three sources are enough. Recheck current URLs, access plans, terms and licences at the point of use. A URL is a lead, not an observation. Existing project identity outranks library recipes. Contrast must be checked after rendering. A pattern's presence is not proof of poor design.
